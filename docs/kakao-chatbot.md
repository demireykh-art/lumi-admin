# 카카오 챗봇 · 재진 CRM 자체 구축 (결정·아키텍처)

**결정일**: 2026-08-11 · **상태**: 방향 확정 (Phase 1 착수 대기)
새 세션 시작 시 이 문서 + `docs/integrated-app.md` 참고.
상담챗 웹훅 스텁은 `functions/index.js`(`webhookKakao`·`sendChatReply`) 참고.

---

## 1. 결정 요약

- 카카오채널 **인바운드(자동응대·태깅) + 아웃바운드(재진 발송)를 모두 통합앱에 자체 구축**한다.
- **애프터닥(외주 SaaS) 중단** — 연 500만원 고정비 + 자율성 제약. 기술력은 우월하나 값은 "두뇌 + 편의"에 대한 값.
- **임시 카카오채널**에서 안정화 → **신규 문의부터 데이터 축적**. 기존 데이터 마이그레이션은 **하지 않음**.
- 유일한 무거운 관문은 **상담톡 API 파트너 심사** → **Phase 4로 분리**. Phase 1~3은 심사 없이 진행.

---

## 2. "전부 우리꺼"의 정확한 의미

카카오는 자체 서버로 메시지를 **직접 발송하는 것을 누구에게도 허용하지 않는다.**
그래서 "전부 우리꺼" = **두뇌는 우리가 만들고, 발송 배관은 임대**한다는 뜻.
자율성은 두뇌에 있고, 두뇌가 우리 것이면 절감 논리도 성립한다.

| 구분 | 항목 | 주체 |
|---|---|---|
| 🧠 **Build (우리 것)** | 오픈빌더 스킬서버(자동응대 로직), 시술명·관심사 태그 체계, 환자 매칭, 재진 세그먼트·타이밍 규칙, 대시보드 | Firestore + Cloud Functions |
| 🔌 **Rent (임대)** | 발신프로필, 알림톡/친구톡/브랜드메시지 발송 API, 템플릿 심사 | 공인 중계사(대행사) · 건당 과금 |
| 🚧 **Gate (관문)** | 사람 1:1 상담을 *우리 앱에서* 수신·응답·캡처 | 카카오 상담톡 파트너 심사 (Phase 4) |

## 3. 전체 흐름 — 3계층

```
INBOUND (자동응대)
  환자 → [카카오채널] → [오픈빌더 챗봇] --webhook--> [스킬서버(우리 CF)] --태그 write--> [Firestore]
                                              ↖───────────── 응답 반환 ─────────────╯

HANDOFF (사람 상담)
  [오픈빌더] --상담직원 연결--> [채널 관리자센터(무료 직원앱)]  ·· Phase4 승격 ··> [상담톡 API = 우리 앱]

OUTBOUND (재진 발송)
  [Firestore] --태그로 추출--> [세그먼트 쿼리] --발송 요청--> [발송 대행사 API] --알림톡/친구톡--> 환자
```

핵심: **같은 `Firestore`가 인바운드의 종점이자 아웃바운드의 시작점**이다.
챗봇이 붙인 태그가 그대로 재진 세그먼트의 기준이 된다.

- 파란 상자(카카오·대행사) = 임대 / 청록 상자 = 우리 구축 / 점선(상담톡) = 심사 게이트.

## 4. 환자 매칭 전략 (Phase 2 핵심)

**신규 수동 입력** 기준. 기존 데이터 이관 없음.

- **1차 키: 이름 + 차트번호(Vegas 기준)**
  - 통합앱 `chartNo` = Vegas 차트번호 (기존 `visits`·차팅과 동일 규칙, `charting-v2.md` §6)
- **교차검증: 전화번호(phone)**
  - 이름·차트번호는 **휴먼에러(오타·동명이인·차트번호 착오)** 가능 → 전화번호로 2차 확인
  - 전화번호는 **채널이 바뀌어도 유지되는 안정 키** → 임시→운영 채널 전환 시 매칭 승계에 유리
- **입력 방식**: 상담 중 직원이 **수동 입력**(자동 매칭 아님). user_key는 채널 스코프 익명 ID라 자동으로 이름·번호를 주지 않음.

> ⚠️ **user_key 주의**: 카카오 `user_key`(=`externalThreadId`)는 **채널마다 다르게 발급**된다.
> 임시 채널에서 붙인 매칭은 운영 채널로 자동 승계되지 않는다. 매칭 키를 user_key가 아닌
> **이름+차트번호+전화번호**로 잡아두는 이유가 이것 — 채널이 바뀌어도 사람 기준으로 다시 이어진다.

## 5. 데이터 스키마 (기존 컬렉션에 얹기)

신규 컬렉션 최소화. 이미 있는 `chatThreads`·`visits`·`procedures`에 필드 추가.

```javascript
// 기존 chatThreads 문서에 필드 추가 (신규 컬렉션 아님)
chatThreads/{id} {
  provider: 'kakao',
  externalThreadId: user_key,          // 채널 스코프 익명 ID (채널마다 다름)

  // ─── 환자 매칭 (Phase 2, 수동 입력) ───
  patientRef: {
    chartNo: '12345',                  // 1차 키 (Vegas 차트번호)
    patientName: '홍길동',              // 1차 키 (이름)
  },
  phone: '010-0000-0000',              // 교차검증 + 채널 전환에도 견디는 안정 키
  matchStatus: 'matched' | 'unmatched' | 'ambiguous',  // 동명이인·오타 대비

  // ─── 태그 (Phase 1, 챗봇/상담원 부여) ───
  tags: ['재진의향', '가격문의'],        // 자유 태그 (funnel)
  procInterest: ['BOTOX_TRAP_100U'],   // procedures.procId 연결 → 재진 세그먼트 기준
  interests: ['쳐짐', '색소'],           // 수가표 상담 태그 재사용

  // ─── 재진 발송 ───
  marketingConsent: true,              // 마케팅 수신동의 (재진 발송 전제)
  lastVisitAt: '2026-05-02',           // visits에서 파생 → 경과일 계산
}

// 태그 사전 (관리자 편집) — settings에 추가
settings/chatTagTaxonomy {
  procedureTags: [...],  interestTags: [...],  funnelTags: [...]
}
```

- `procInterest` 는 `procedures/{procId}` (수가표 자동 파생, `charting-v2.md` §3.1) 를 참조.
- `interests` 는 수가표 상담 태그(피부/쳐짐/꺼짐/전문) 체계를 재사용.
- Firestore 규칙: `chatThreads` 는 이미 `signedIn()` 허용(`firestore.rules` 71~73행). 필드 추가는 규칙 변경 불필요.

## 6. 구현 로드맵

기존 `webhookKakao`·`chatThreads` 스캐폴드 재활용. Phase 1~3은 심사 없이, Phase 4만 상담톡 관문.

### Phase 1 — 우리 챗봇 (인바운드 자동응대 + 태깅)
- `webhookKakao` 스텁을 **오픈빌더 스킬서버 스펙**으로 개조
  - 요청: `userRequest.utterance`, `userRequest.user.id`
  - 응답: 스킬 응답 JSON (`template.outputs`)
- 시나리오·폴백(영업시간·시술·예약 안내) + 시술명·관심사 태그를 `chatThreads` 기록
- 사람 필요 시 "상담직원 연결" 폴백
- **산출물**: 채널 문의가 우리 로직으로 자동 응답, 태그가 Firestore에 축적

### Phase 2 — 환자 매칭 (§4)
- 상담 중 직원 **수동 입력**: 이름 + 차트번호(1차) + 전화번호(교차검증)
- `chatThreads.patientRef`·`phone`·`matchStatus` 기록 → `visits`(chartNo)와 연결
- **산출물**: 문의자가 실제 환자 차트와 연결

### Phase 3 — 아웃바운드 재진 발송
- 대행사 1곳 선정 · 발신프로필 · 알림톡 템플릿 심사
- 우리 태그로 **세그먼트 쿼리 → 발송 API 호출** (예: 보톡스 3개월 경과 → 리마인드)
- 마케팅 수신동의·의료 민감정보 관리 포함
- **산출물**: 애프터닥 핵심(재진 자동 발송)을 우리 태그 기준으로 대체

### Phase 4 — 상담톡 승격 (심사 게이트, 선택)
- 카카오 **상담톡 API 파트너 심사** 통과
- 사람 1:1 상담을 우리 앱 화면으로 흡수, 대화 로그 우리 DB 캡처
- **산출물**: 자동응대~사람 상담~재진 전 구간을 통합앱이 소유
